# Ялинка — тестування веб-ресурсу онлайн-магазину

Навчальний веб-ресурс на тему «Тестування веб-ресурсу онлайн-реалізації продукції універмагу “Ялинка”». Сайт поєднує вітрину магазину з робочими сценаріями пошуку, фільтрації, керування кошиком, оформлення замовлення та перегляду даних у кабінеті працівника.

## Сценарії для перевірки

- пошук товару та фільтрація за категорією;
- додавання товарів у кошик, зміна кількості та синхронізація підсумку;
- валідація форми й збереження замовлення у PostgreSQL;
- адаптивне відображення сторінок магазину та кабінету.

## Запуск локально

Потрібен Node.js 22 або новіший та база PostgreSQL у Neon. У PowerShell задай рядок підключення з панелі Neon:

```powershell
$env:DATABASE_URL = "postgresql://..."
npm ci
npm start
```

Сайт буде доступний за адресою `http://localhost:3000`. Змінна `DATABASE_URL` має бути задана в тому самому PowerShell-вікні перед запуском.

Для автоматичного перезапуску під час розробки:

```bash
npm run dev
```

## База даних Neon

Під час запуску сервер автоматично створює схему `yalynka` з таблицями `products`, `orders` та `employees`, а також додає демонстраційні товари й працівників, якщо їх ще немає. Окрема схема не перетинається з таблицями інших сайтів у тій самій базі Neon. Каталог і замовлення зберігаються в PostgreSQL Neon. SQLite-файл не використовується; раніше створені локальні SQLite-замовлення автоматично не переносяться.

## Публікація

Проєкт можна розмістити на Render, Railway, VPS або іншому Node.js-хостингу:

1. Додай репозиторій GitHub до сервісу хостингу.
2. Команда збірки: `npm ci`; команда запуску: `npm start`.
3. Додай `DATABASE_URL` у налаштування змінних середовища хостингу (візьми connection string у Neon).
4. Після розгортання перевір `/api/health` — відповідь має містити `"database":"connected"`.

Не додавай `DATABASE_URL` у Git або в код. Зупинка чи повторний деплой веб-сервісу не видаляє дані з Neon.
